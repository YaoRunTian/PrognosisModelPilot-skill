# 参考方案和报告的文档格式

2026-10-28起，正式方案和报告默认匹配用户提供的项目材料，而不只是复用其章节摘要。依据分别见 [proposal-map.md](proposal-map.md) 的25份方案和 [report-map.md](report-map.md) 的19组Word/PDF报告。不同年份和项目有版式差别，先选具体参考，不把一次抽查看到的字号、颜色或目录当作全部材料一致的规范。

## 选择和保留格式

1. 用户已指定参考原件时用该版本；未指定时优先按分析路线选择，如Scissor/hdWGCNA参考project001，关键细胞/虚拟敲除参考project002、project004或project005，基础bulk参考project007。选择不要求同癌种，不以项目是否完成过滤方案参考。
2. 记录方案与报告各自的文件路径、SHA256/版本、参考页和格式提取依据。方案本地原件根目录为`<本地方案目录>/`；报告原件在`<参考项目根目录>`下，对应文件名见报告地图。取得原件遵循本次可用连接和既有授权，认证信息不进入技能或文档。
3. 可读取Word时，检查`document.xml`、`styles.xml`、`numbering.xml`、主题与节属性以及原PDF/实际页面。字体、字号与段落可能写在具体run或段落中，不能只看Normal样式；最终生效格式须按直接格式、样式继承和主题解析。
4. 在工作副本中保留可用的页面/样式/编号/目录/图题/表格定义并替换正文，或者依据提取的格式重新构建。清除不属于本项目的正文、旧数据、旧图、作者信息与项目编号；保留版式不等于沿用旧结论。不能在原件上直接覆盖。
5. 原件暂不可访问时，按下述已学结构和已记录样式完成可确认部分，标注“依据学习提炼、未直接比对原版式”的限制。不声称精确复刻；后续原件可用时补对照。无需因为无法精确复刻而放弃已授权的正文和图表整理。

## 需要继承的具体内容

| 对象 | 与参考核对的内容 |
|---|---|
| 封面 | 题名、项目编号、日期的位置、对齐、字号、留白和分页；替换成当前项目身份 |
| 页面 | 纸张、方向、边距、节、页眉页脚距离、页码、正文区宽度 |
| 目录与标题 | 参考使用目录时保留并更新域；多级章节和分析点编号、字体、粗体、段前后和与下段同页 |
| 正文 | 中文及西文字体、字号、首行缩进、对齐、行距、段距、列表与引用习惯 |
| 重点内容 | 随参考区分队列、参数、结果与目录的颜色/强调方式；不把示例显著性当实际结果 |
| 图像 | 居中、宽高比例、分面和清晰度，与下方图题/图注相邻；不截断坐标/图例 |
| 图题与图注 | Fig/图编号体系、字体、间距、分面释义、检验与单位；文内引用和源文件一致 |
| 表格 | 标题、表头、边框、对齐、字号、列宽、单位与跨页表头，避免过宽和断裂 |
| 尾部章节 | 总结、调整、软件列表、质检、参考文献的顺序及写法；检查状态按实际填写 |

已学报告的常见视觉习惯是黑色粗体多级标题、图片居中、下置图题/注释，蓝色标队列、绿色标参数、红色标关键结果/结果目录，早期来源段另有黄色标记。按所选参考具体应用，不把所有正文统一染成彩色，也不改为通用卡片式展示稿。

## 可核实的方案版式样本

2026-10-28再次读取本地`project005单细胞+转录组预后方案.docx`的OOXML，观察到：A4纵向（11906×16838 twip），上下边距1440 twip、左右1800 twip，单栏；默认中西文字体声明为宋体和Times New Roman。正文大量直接run格式使用24半磅即12pt，题名样本32半磅即16pt；常见直接段落行距360、`lineRule=auto`即1.5倍。其Normal样式另声明10.5pt，说明不能只复制Normal而忽略直接格式。该记录只代表project005方案，不被当作19份报告共用的字号规范；源文件哈希见方案来源索引。

中文字体须在实际生成/渲染环境可用。优先保留参考字体；若缺失则明确映射到可用中文字体并复核换行、页数及图表位置，记录映射。此前project005工作副本抽查存在中文缺字，属于旧文档渲染限制，不是新文档可以交付缺字页面的依据。

## 方案正文结构

参考方案通常按题名/编号、背景、方法概览、研究目标、拟解决科学问题、创新性、流程图、数据准备、逐分析点设计和参考文献组织。根据选定参考保留原标题和层级；模板中为了规划新增的可行性、依赖、修订表可放相应章节或附表，不为模板形式重排用户原有设计。

逐分析点沿用“目的、使用哪个队列、方法与阈值、Fig及图型”的具体写法。正式方案中插入本项目技术路线，另交PNG和可编辑PPTX。示例结果图只作图型说明时标明来源与非本项目结果，预分析另列数据、参数、来源和局限。没有预分析时不生成虚构统计图。

## 报告正文结构

较新报告默认“项目概述 → 分析结果 → 项目总结 → 项目调整 → 软件列表 → 报告质检 → 参考文献”，概述含背景、方法、数据、目标/问题、设计特点和流程。选择早期报告作模板时可保留其章节结构，内容仍按实际数据流排列。

每个结果分析点依参考写“目的、数据/比较、实际方法与参数、定量结果、对应图表、结果目录”。真正插入本次结果图片，图题位于图下，必要表格在相邻正文；补充图表有定位，不用一张概念总览替代所有结果。候选、系数/PH、质控/marker、通路、软件及质检表按当前工件填写，保留参考表格风格。正文结果与源文件、独立图片及清单中的图号逐项对应。

## 生成与核查

默认输出可编辑DOCX和对应PDF，文件名继承参考的项目编号及方案/report日期习惯。Markdown只作起草与内容索引；PPT只作技术路线或用户单独要求的演示，不能替代正式方案/报告。Word需要真实表格、图片和可编辑文字，不能将整份报告贴成截图。

使用当前可用的文档/PDF工具按其流程生成与渲染。先对照参考封面、正文分析点、图表页和尾部表格，再检查新文档全部页：中文、分页、标题孤行、图题分离、表格跨页、公式、页码、目录和交叉引用。更新目录与字段后再导出PDF；核对Word嵌图、PDF图像和独立PNG/PDF均对应同一结果版本。渲染成功不等于内容正确，文件结构检查也不证明版式已通过。

交付前在`deliverables.tsv`和报告证据索引记录正式文件、独立图表、模型与结果来源，按 [output-contract.md](output-contract.md) 逐文件检查。未做的检查写待核查，不预填“无问题”；格式偏离记录具体原因、替代字体或受影响页面。
