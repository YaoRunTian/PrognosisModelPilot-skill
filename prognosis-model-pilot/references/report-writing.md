# 生信实验报告写作

从19个项目主报告学习的写作模式，来源与覆盖见 [report-map.md](report-map.md)。这些主要是生信分析结果交付报告；标题里出现“实验验证”或方法列表列出RT-qPCR，不足以证明实验已经完成。写作以当前项目的实际结果为依据。

方案的设计写法另见 [proposal-writing.md](proposal-writing.md) 和 [proposal-map.md](proposal-map.md)。报告需对照方案版本记录队列、样本纳排、终点、模型路线及模块的实际变化；方案中的预期输出、示意图片或预分析不能自动转为正式结果。本次方案学习未审定各项目最终是否完成或通过，不据此给报告状态补标签。

默认新项目沿 [core-workflow.md](core-workflow.md) 叙述：可选单基因表达定位 → 关键细胞与G1 → bulk的G2与可选通路G3 → 交集候选 → 单因素Cox、LASSO、多因素Cox → 评分、评价和临床列线图 → 预后基因/风险组及关键细胞两条下游。完整设计中的未完成模块进入调整/待补记录；旧项目实际采用其他顺序时不改写其真实方法。

采用 [department-standards-v5.md](department-standards-v5.md) 的参数、证据和交付要求，使用 [standards-review.template.tsv](../assets/standards-review.template.tsv) 组织标准核查。每项记录“部门要求、实际值、证据、状态、偏离及已有确认”；性能目标与真实估计分别陈述。原文涉及忽略失败验证、删图或换检验等条款按参考中的对照说明处理，不把未达标结果写成通过。

## 输入与结果来源

优先读取当前配置、实际运行的脚本版本、结果表、模型对象、日志、图及队列元数据。取得报告主题、受众、输出格式、参考报告、结果根目录及版本；已经明确的内容不重复询问。仅要求撰写报告时，不重新下载数据、训练模型或提交计算任务。

建立一张结果来源索引，可从 [report-evidence.template.tsv](../assets/report-evidence.template.tsv) 开始。每行对应一个可核查数值或实质性结论，标明章节、队列及角色、文件、行/列或对象位置、指标和值、单位、比较方向、方法、核查状态和关联图片。状态使用“已核实、待核实、存在冲突、未完成、不适用”等真实值。

数字从表或对象读取，不能只凭图片目测小数、旧报告文字或文件名填入。图中可读但尚无底层表的值要记录图号与限制；需要精确统计值时优先找生成表或日志。若报告、脚本和输出有差异，先核对运行版本及工件，不自动认定其中某一方正确。未解决冲突的指标不能进入确定性总结。

常见来源：样本纳排和分组表、差异分析表与候选列表、单细胞对象与质控统计、模型/系数/预处理工件、KM与ROC数值表、富集结果、药物预测结果，以及`sessionInfo()`。旧项目报告属于风格参考，不属于新项目结果证据。

## 组织结构

以 [analysis-report.template.md](../assets/analysis-report.template.md) 为可裁剪提纲，沿用较新报告的层次：

1. **项目概述**：背景、实际方法、数据来源、研究目标和问题、设计特点及流程图。背景引文与疾病统计需核验；没有文献对照时不声称“首次”。流程图区分已完成、未完成及计划步骤。
2. **分析结果**：按数据流组织已完成模块。bulk先建模再做单细胞解释，与单细胞先筛候选再建模应采用不同顺序。每节包含数据/比较、方法与实际参数、定量结果、图表及文件位置。
3. **项目总结**：围绕研究问题整合主要发现、解释、局限和后续验证，不重复罗列软件或全部分析步骤。数字与正文一致，不增加正文没有支持的实验或性能结论。
4. **项目调整**：记录原计划、实际变化、原因与影响。记录失败、缺数据、不显著或队列角色变化，不为取得显著结果自动换队列、阈值或种子；历史任务存在这类选择时如实说明验证边界。
5. **软件列表**：软件/包、实际版本、用途与必要引用。由本次运行记录取得，不能复制参考报告中的版本表。
6. **报告质检**：逐项记录已检查内容、结果、定位和待办；没有完成的检查保持“待核查”，不预填全部通过。
7. **参考文献**：引用实际支持背景、方法或讨论的文献和数据库；核实标识符与内容，不照搬旧参考文献的编号或声称已全部核验。

本技能不要求机械复用固定目录编号。可保留项目既有编号与结果目录，图表号则按本次正文顺序生成并交叉引用。删除模块后同步调整目录、流程图、图表号与总结。

## 绘制与核对报告流程图

参考 [report-flowcharts.md](report-flowcharts.md) 的实际图示组织方式。默认把单细胞/关键细胞、bulk/候选交集、预后建模与验证、临床列线图和两条下游按依赖展开；清楚标明G1/G2/可选G3与训练、内部及外部队列。独立单细胞机制分析可以并行，验证队列箭头应进入评价节点；真实执行另受患者隔离及折内筛选约束。

箭头表达数据或对象依赖，不能仅为排版把并行分析画成前后筛选。虚线、颜色、分组框和结果缩略图的含义须有一致图例；报告中的示例结果图只用本次有来源的工件，不从旧图复制。关键细胞、预后基因、风险组和候选集合分别命名，避免把不同对象都写成“关键基因”。

与正文和工件逐项核对队列号、方法位置、筛选顺序及完成状态。图中写“RT-qPCR”或“实验验证”只说明图示节点；要写已完成须另有实验记录。若旧图有截短队列号、遗漏方法或与代码不一致，保留观察和差异，依据实际运行工件写当前报告，不直接复制旧图为新项目结论。

按实际产出呈现风险分布、生存状态、KM、时间依赖ROC、基因表达热图，以及列线图、校准和其他评价图；图题须指向对应队列和模型，不能把所有ROC笼统当成同一种验证。

## 模块写作要点

| 模块 | 必须与当前结果核对的内容 |
|---|---|
| 数据来源与纳排 | 数据库、项目/队列号、平台/数据类型、获取时间、用途、原始与最终样本数、患者去重规则、事件数；细胞数与患者数分别报告 |
| 差异表达 | 明确比较方向与对照、表达输入尺度、方法/设计、效应量和原始p或校正p阈值、上下调及总数；与火山图和热图一致 |
| 候选整合与富集 | G1、G2及启用时G3的来源/数量、ID映射、实际交集、最终基因列表、富集输入及背景、数据库版本与多重校正；G3未启用须写明，不能把前一项目基因数带进富集段 |
| 单细胞质控与注释 | 样本/患者、质控前后细胞及基因数、实际阈值、批次处理、降维/聚类参数、marker与注释依据；人工注释和自动注释分开说明 |
| Scissor与网络 | bulk表型的真实编码、Scissor正负方向、目标细胞、网络/模块选择规则及数目；不能仅凭“Scissor+”就称为耐药细胞 |
| 虚拟敲除及其他计算机制 | 目标基因/细胞、输入层、具体实现、扰动与筛选规则、效应方向及富集；写成计算推断，不能当成实验敲除或已证实因果 |
| 预后建模 | 终点与单位、训练样本/事件数、患者级划分、特征筛选和调参、实际模型类型、CI水平、最终特征与系数、表达转换、评分公式及分组规则 |
| 临床列线图 | 基因模型与临床联合模型的区别、评分及临床变量编码、联合模型对象、基线生存、预测时间单位、列线图和实际校准/评价；不能仅凭图片声称已验证 |
| 模型评价与验证 | 队列角色、冻结还是重新估计阈值、分组数、实际检验、效应与不确定性、时间点、C-index/时间依赖AUC/校准等实际计算指标；内部、外部及合并结果分开 |
| 分类或表达验证 | 写明分类标签或表达比较，不将分类AUC、表达一致性、SHAP或基线表结果改写成生存预测能力 |
| 免疫、药物与分子模拟 | 计算方法、样本、比较与校正、分数含义及候选排序；预测反应、对接及模拟结果不能直接改写为临床疗效或药敏实验已验证 |
| TMB及突变 | 受检患者及突变来源、过滤规则、负荷定义及每Mb分母、实际可用数量、表达/评分关联或风险组比较；未受检缺记录不计为零 |
| 关键细胞拟时序、通讯与代谢 | 细胞及患者范围、根节点与对照状态、通讯所需其他细胞、数据库及参数、实际图表；明确计算轨迹/相互作用/代谢分数的解释范围 |
| 湿实验验证 | 仅在有真实实验记录时纳入；记录样本、实验设计、对照、重复、测量与统计结果。没有材料时列待补，不能根据标题或流程图补写实验结论 |

评分公式尤其要核对最终工件：线性预测值、`exp(lp)`及绝对生存概率不得混写；LASSO筛选后是否又做多变量Cox再拟合必须按实际实现描述。PH检验函数、CI水平与KM检验名称也不能复制通用段落。没有执行的算法即使出现在计划或载入包列表中，也不写成已使用的方法。

## 正文与图表的写法

一个结果段落回答：为解决什么具体问题，在什么样本上，用什么方法和参数，得到什么定量结果，以及该结果支持到什么程度。方法说明与结果紧邻，但不复制大段通用算法教材。结果有统计支持时报告适当的效应量、CI与p/FDR；不显著时如实写未达到预设阈值，不强行改为“无效”或删去。

图题说明图的主题；图注给出分面、坐标与单位、样本与分组、颜色/符号、统计检验和多重校正。星号阈值以本图实际绘制规则为准。每张图和表必须在正文中被提及，文件索引须指向真实可打开的工件。候选集计数、风险组样本数和图中数字须与源表相符。

保留原报告有用的“本节结果见某目录”的追溯方式，并记录准确文件名。提供清晰图片及可用的原始矢量图时检查是否一致，不宣称不存在的PNG/PDF已经交付。

## 总结与证据强度

总结优先回答研究问题，再说明主要量化证据、跨队列一致或不一致之处、候选解释与剩余限制。不能根据AUC超过某固定数值就断言临床可用，也不能仅凭关联、富集或模拟断言机制已经证实。

训练集表现、内部留出、独立外部验证及训练测试合并结果分别命名。验证集重新优化切点需说明其探索或更新性质。缺预处理参数、来源不明、样本混用或尚未解决的计算问题会影响哪些结果，应写清而不是用流畅叙事掩盖。

## 文档样式与交付

用户已明确要求与学习的报告格式基本一致，参考报告样式现在是默认要求，具体按 [document-format.md](document-format.md) 执行。参考报告常见黑色加粗多级标题、居中图片及下置图题，正文中用蓝色突出队列、绿色突出参数、红色突出关键结果或结果目录；早期报告还使用黄色背景标记来源。优先选择一个路线相近的报告并继承其实际封面、目录、字体、段落、表格及图题/注释样式，不随意重设计成卡片式简报，不复制旧项目编号、署名或单位信息。

默认可编辑DOCX及对应PDF；用户指定Markdown等格式时遵从。先完成正文、证据和图片对应，再使用可用的documents/pdf工具渲染并检查全部交付页，核对中文字体、图分辨率、表格断页、公式、页码、目录与交叉引用。提取XML时封面文本框可能重复、Word属性页数可能陈旧，不能把提取伪影当作实际排版。

每个已完成模块的主要结果须实际嵌入相应图表，写清图题、分面、队列与结果目录。按 [output-contract.md](output-contract.md) 同时交付独立PNG/PDF、底层结果表及模型工件；仅有图注、结果文字、绘图代码或失效外链均不算完成图表交付。`deliverables.tsv`的文件、报告图号和`report-evidence.tsv`须指向同一运行版本。

质检至少覆盖参考报告中的19类问题：题名、目录、流程图、数据、疾病名、数字、图片匹配、图片清晰、方法与阈值、图注、每个分析点的结果、来源目录、总结、方案调整、软件版本与用途、参考文献、格式、结果文件、代码与可复现性。每条记录实际证据和状态；检查未覆盖或有冲突时不得写“全部无问题”。
