# 项目方案撰写与修订

本模式从用户提供的25份方案提炼，来源和覆盖见 [proposal-map.md](proposal-map.md)。学习各类方案的论证、模块衔接和表达方式，不以服务器项目是否完成筛选参考。不将旧方案的拟定方法、示意图、预期结果或参考论文结果当作新项目的事实。

## 选择任务与输入

先取得癌种及亚型、目标人群、研究终点、关注单基因或生物学方向、现有数据与工件、方案受众、参考样式及交付格式。用当前材料填充 [project-proposal.template.md](../assets/project-proposal.template.md)，用 [proposal-module.template.tsv](../assets/proposal-module.template.tsv) 记录具体模块。能够从会话和文件确定的信息不重复询问；真正缺失的设计项标明对哪些模块有影响，继续可确定部分。

任务边界：

- **学习参考方案**：阅读结构、数据角色、科学问题与模块写法，更新技能和模板；不自动替用户做新研究或运行来源代码。
- **新写方案**：核对必要来源，形成与本项目匹配的设计、数据表、技术路线、模块计划、预期交付及待解决项。
- **修改方案**：保留用户确定的研究问题，对新增或变更模块记录旧值、新值、理由和影响，更新相关流程图与图号。
- **方案加预分析**：仅在当前任务包含或已有授权涵盖预分析时执行相应阶段。仅有写作请求时可以读取已有预分析，不自行启动模型训练、大规模数据下载或计算任务。

## 组织方式与具体写法

参考方案常见“背景→方法概览→研究目标→拟解决的关键科学问题→创新性→流程图→数据准备→逐分析点设计→参考文献”的组织，部分另列预分析。保留其具体、可执行的特点，章节顺序可以按受众调整。

| 部分 | 写作目标 | 易混淆之处 |
|---|---|---|
| 题名 | 点明癌种、切入方向与研究类型 | 不在题名预判关键细胞、最终基因或机制成立 |
| 背景 | 疾病或治疗问题→生物学方向→证据缺口→本设计为何能回答 | 不堆叠算法介绍；疾病统计、缩写和引文另核验 |
| 方法概览 | 简洁概括实际拟用路线及两条下游 | 与详细模块对应，不将所有学过的方法列入本项目 |
| 研究目标 | 说明拟完成的研究工作和交付，例如鉴定候选、评估预测、刻画细胞状态 | 与性能承诺或结果陈述分开 |
| 科学问题 | 说明待检验的关系、差异、可重复性及生物学解释 | “运行某包”不是科学问题；关联问题不直接写成因果机制 |
| 拟创新点 | 指出研究对象、数据整合或问题角度的具体特点和文献对照 | 未核验系统检索时不称“首次”；不以简单叠加算法作为充分创新证据 |
| 数据准备 | 每个队列的平台、组织、人群、终点、字段、纳排与角色 | 数据库总例数、纳入患者数、细胞数及事件数分别记录 |
| 技术路线 | 显示队列、基因集合、筛选、模型、验证与下游的依赖 | 建模后单细胞解释不能画成上游筛选；外部队列箭头进入评价阶段 |
| 逐模块设计 | 目的、输入、方法/参数、预期工件和依赖 | 图型是计划，不提前填入显著差异、基因数、AUC或示例结论 |
| 可行性与调整 | 数据能否支持、缺项、限制、复核或停止条件 | “效果不好再更换数据直到通过”不能作为设计策略 |
| 交付与参考 | 方案、计划表、图表类型、代码/实验边界和可靠来源 | 明确承担方；未做的实验不写成完成 |

逐分析点可以采用参考方案的句式，但填入本项目的对象和选择依据：

> 为了回答〔具体问题〕，拟在〔队列角色、患者或细胞对象〕中，使用〔输入及尺度〕，采用〔方法与设计〕并按〔参数及来源〕分析；计划导出〔表格、图型及字段〕。该步骤依赖〔上游工件〕；若〔数据或方法条件不满足〕，则〔复核、保留未完成或有依据的修订步骤〕。

避免将每节写成相同的泛泛背景。标题中可保留“在开发队列中”“在独立验证队列中”“在关键细胞中”等限定，方便核对数据用途。

## 队列与来源核验

数据表至少区分**发现/特征筛选、模型开发、内部评价、独立外部评价、机制解释、表达验证、治疗反应评价**。同一个数据集可承担多个已声明的开发用途，但不能同时作为独立外部评价。细胞系放疗或药敏标签不能改名为患者生存结局，表达验证不能代替预后验证。OS、DFS与PFS不互换；不以“带生存数据”笼统保证终点一致。

撰写真实新方案时，通过数据库记录、原论文及补充材料核验队列号、组织/亚型、平台、可下载文件、随访终点、事件字段和患者重叠。区分“文献报告例数”“已下载可用数”“纳排后数”和“未知”；没有实际纳排时不预填最终样本量或事件数。相关说明标注来源、核验时间和状态。重要方法引文需核对标题、标识符与支持的内容，旧方案中的PMID和数据库链接只是线索。

TCGA获取仍按 [tcga-acquisition.md](tcga-acquisition.md) 的用户指定方式规划：TCGAbiolinks获取GDC公开STAR - Counts及单独临床表。联合疾病名称须映射到实际项目，如肺癌不能仅填写“TCGA-NSCLC”当作可查询项目。既有数据优先核对再复用。RNA-seq、芯片和表达尺度由源数据确认，不沿用旧方案可能误写的测序方式。

具体数值标准引用 [department-standards-v5.md](department-standards-v5.md)，不在方案中另建冲突的默认值。参数应标“部门默认、用户指定、文献依据或待确定”。数据驱动参数应写选择规则，例如训练折内选择lambda，而不是写一个假定的最佳值。LUAD完整预后方案需规划独立外部评价；未找到适用队列时写明该模块待补及交付限制。

## 规划主线与模块

默认路线按 [core-workflow.md](core-workflow.md)：可选单基因定位→关键细胞→G1；bulk筛选G2；可选功能/通路G3；启用集合取交集→单因素Cox→LASSO-Cox→多因素Cox→评分与临床列线图。G1的提取方式由研究问题决定，不能把marker、Scissor、hdWGCNA和虚拟敲除全部强制串联。复现旧方案或用户指定先bulk建模再单细胞解释时，如实标注路线差异。

在方案阶段写清模型开发与评价隔离：患者级划分、训练折内的学习与筛选、模型及表达转换冻结、验证沿用特征和分组规则。最终系数取自多因素Cox；列线图另以风险评分结合临床因素建立联合模型。评价时间点依据随访覆盖和单位确定，不能为了凑齐图型承诺不受数据支持的年限。

核心模型问题与探索模块可并行安排，按现有材料确定先后；下表帮助把依赖写具体：

| 模块 | 设计中须明确的输入/前提 | 预期工件示例与解释边界 |
|---|---|---|
| 单细胞定位和G1 | 患者/样本、counts或对象层、质控、批次、marker依据、关键细胞判定及G1提取规则 | 质控与注释表、表达图、关键细胞依据、G1及来源；不提前锁定某cluster |
| Scissor / hdWGCNA等选用方法 | bulk真实表型、标签正负含义、跨数据基因映射；样本/细胞及网络构建条件 | 关联细胞或模块及参数表；正负标签必须按编码解释 |
| bulk与候选整合 | 原始counts或适用芯片、比较与协变量、ID映射、G3来源及版本 | 差异全表、G1/G2/G3表、交集及计数图；空交集仍是可记录结果 |
| 模型与评价 | 匹配的表达/生存、患者与事件数、预处理、筛选/调参/PH规则、独立队列 | 模型、系数、风险值、KM、删失生存评价和校准；不承诺入模数和AUC |
| 临床列线图 | 风险评分、至少一项适用临床变量、编码、缺失处理和预测时间 | 联合模型、列线图、校准及评价表；与仅基因评分区分 |
| 免疫/治疗/药敏/TMB | 评分方法和资源；真实治疗队列或代理指标；药敏训练资源；突变受检清单及分母 | 比较及关联全表和图，区分计算预测、实际治疗结局和未受检缺失 |
| 关键细胞轨迹、通讯、代谢 | 轨迹根与生物学依据；通讯的其他细胞和配受体库；代谢基因集 | 轨迹、通讯网络、代谢分数和统计表；不等同细胞谱系证明或代谢通量实测 |
| RNA velocity（条件扩展） | spliced/unspliced等相应输入及方法适用性 | 有输入时再设计；普通归一化对象不足以宣称可运行 |
| 虚拟敲除/调控/分子模拟（条件扩展） | 目标、上下游位置、模型输入；结构/配体来源及选择依据 | 计算扰动、网络、对接或模拟结果；各自支持的推断范围分别写明 |
| 湿实验（按任务） | 承担方、可用样本/细胞系、伦理及材料条件、对照、独立重复、测量和统计设计 | 实验计划和实际可交付数据；样本量依据目标效应与可行性讨论，不照搬“五对样本” |

## 证据层级、示意图与可行性

四类内容在正文与图注中显式区分：

1. **设计假设**：尚待检验，用“拟探索、评估是否、计划比较”。
2. **文献或出图示意**：仅说明预期图型，标注来源及“非本项目结果”；不把原图的疾病、基因或性能改成新项目数据。不需要示意图时只列图表清单。
3. **已有预分析**：记录具体数据版本、样本、脚本、参数、结果工件与限制。正式方案与预分析的数据或纳排不同，单列差异；无法取得底层文件时标为“来源文档所述、未复核”。
4. **正式结果**：由实际运行支持，转入 [report-writing.md](report-writing.md) 及结果证据索引；不在方案阶段凭预期补写。

方案可行性与历史执行状态分别记录。可行性可为“未核验、来源核验支持、预分析支持、部分受阻”等，并列出证据；执行状态可为“未核验、未启动、部分完成、完成、停止”，仅依据真实记录赋值。服务器缺报告、缺结果目录或本地仅有方案时保持未核验，不能代替用户解释项目未完成原因。

调整条件写为可复核决策，而不是追求阳性：

- **缺终点或独立队列**：记录不满足条件的字段和来源；开发与探索仍可单列，完整外部验证保持待补，不把表达验证或内部合并替代为独立验证。
- **零候选/无可用模型、PH问题或事件不足**：先核对ID映射、样本和编码、方法假设与信息量，保留原结果。确有科学依据的设计修订另建版本、说明受影响评价；不反复改集合、阈值、种子或队列直到显著。
- **选用模块缺原始输入**：明确具体依赖，暂不列为已具备条件；如用户允许等价替代，说明它回答的问题及与原方法差别，不静默改名。
- **独立验证或下游未达预期**：照实纳入交付与局限，不删除负结果；探索性发现与后续独立确认分别规划。

## 交付与检查

仅写方案时，默认交付参考方案样式的正式DOCX及对应PDF，包含正文、数据与角色表、已嵌入的技术路线、分分析点的拟输出图表、可行性和待补项，另交技术路线PNG、可编辑PPTX及模块计划。用户明确要求其他格式时从其要求。预期交付清单按任务列出将来分析工件，不冒称这些工件已经生成；Markdown提纲不是正式Word方案的替代品。

按 [document-format.md](document-format.md) 选取路线相近的参考方案，继承题名/项目编号、章节顺序、正文与方法段、图题、页面和字体格式；与 [output-contract.md](output-contract.md) 的文件清单对应。用可用文档工具生成并渲染核对中文、表格、流程图、页码和交叉引用。内部旧文档渲染若缺字体，保留XML阅读与原图检查的覆盖说明；新文档仍需解决可用字体和导出问题后检查，不能把旧文档的渲染局限当成新交付免检理由。

提交前核对：癌种与亚型一致；每个科学问题都有对应模块；队列号/角色/终点、G1/G2/G3与模型顺序在正文和流程图一致；方法适用于输入；参数有来源；外部验证未用于选方案；图号指向预期图型而非虚构结果；湿实验责任清楚；引文状态真实；待补和修订条件可以定位。保留有意义的阴性或不可行结果作为可能结局。
