# 新癌种与新队列的项目生成

本技能的首版主任务是生成适配后的分析项目。能独立运行的阶段应有真实实现；信息不足的阶段应有具体诊断。生成项目与执行项目分别依据当前请求及已有授权处理，不因生成代码就自动安装远端包、下载大型数据或提交计算任务。

完整构建请求采用“方案及流程图、R代码、实际分析图表、正式报告”的连续交付路线；具体文件按 [output-contract.md](output-contract.md) 对齐已学习的服务器项目。只要求代码时交付本次实现和明确待运行项；不能把代码已生成写为完整分析已完成。

若用户当前只要求研究设计或项目方案，转入 [proposal-writing.md](proposal-writing.md)。已有方案可以作为项目设计输入，但须重新核对队列角色、终点、实际样本及方法条件；方案不证明数据已取得或分析已完成。将方案版本与正式实现的差异留在变更记录中。

新项目默认采用 [core-workflow.md](core-workflow.md) 的用户指定路线：关键细胞得到G1、bulk筛选得到G2、可选功能通路G3，取交集后依次单因素Cox、LASSO-Cox、多因素Cox，构建评分和临床列线图，并规划两条下游分析。用户指定已有候选、简化任务或历史复现时，只处理实际所需阶段，注明与默认路线的差异。

同时应用 [department-standards-v5.md](department-standards-v5.md)。标准中可配置的默认参数与用户已指定参数分别标来源，记录已确认例外；方法有效性、训练/测试隔离及真实结果报告仍遵循数据与模型契约。

## 取得足够的输入

先从会话、数据字典、项目配置及允许读取的文件取得下列信息。已提供的内容不重复询问；可以把真正阻塞实现的缺项集中为一个短问题，并继续完成不依赖它的阶段。

| 输入 | 需要确定的内容 | 缺失时可先完成 |
|---|---|---|
| 研究目标 | 癌种、预测终点、入组/排除条件、所需输出 | 文件盘点与目标配置草稿 |
| bulk训练队列 | 表达和临床路径、矩阵方向与尺度、患者/样本关系、时间与事件字段及单位 | 通用预检与列映射框架；不能猜事件含义或时间单位 |
| 差异分析输入 | 原始counts或适合的芯片表达、对比定义与协变量 | 若已有候选基因，可从下游开始；缺counts时不伪造DESeq2输入 |
| 单细胞分支 | counts/Seurat对象、患者/批次、可选关注单基因、关键细胞选择依据、G1提取路线 | bulk阶段和单细胞输入预检；未知细胞类型不预设cluster ID |
| 候选来源 | G1、G2来源、是否启用G3及其功能/通路来源，或已确认的候选表 | 按默认交集规则准备追溯表；不能擅自选择目标基因、模块或G3主题 |
| 验证设计 | 内部留出/外部队列、数据定义与独立性信息、拟评价时间点 | 可先生成/运行已授权的内部阶段，但完整预后交付的独立外部验证保持待补；CESC/THCA/UCEC的内部替代方案须有例外确认 |
| 列线图与下游 | 临床变量编码、突变与受检清单、药敏资源、免疫治疗数据或预测方式、关键细胞下游输入 | 规划默认模块并记录具体缺项；不把代理分数当实际治疗反应 |
| 参考实现与输出 | 可读取的参考项目及版本、目标项目目录、允许覆盖范围 | 路线选择、阶段依赖、源码待取清单；不覆盖历史输出 |

生存终点、事件编码、时间单位和表达尺度会直接改变实现；对这些缺项不能以“采用常见默认值”继续计算。差异和Cox等已有部门默认参数可预填，但仍区分部门默认、用户指定值、例外和旧项目原值。折数须按患者与事件数确定，不能照搬样本数规则或把细胞数当可用患者数。

若 TCGA 数据尚未取得，将数据获取阶段加入项目，默认按 [tcga-acquisition.md](tcga-acquisition.md) 使用配套 `download_tcga.R`，将癌种映射为实际的 `TCGA-*` 项目编号。新下载数据默认以 `counts.rds` 接差异分析、以 `log2_tpm_plus1.rds` 作为后续生存建模的表达候选输入，样本筛选、注释及模型预处理仍按具体设计执行；配置中应填写实际路径和 `log2(TPM+1)` 尺度，不能把它改名为FPKM。已经有符合契约的本地数据时直接从整理或下游开始；不要重复下载。获取阶段输出的是原始数据及元数据，不把下载成功等同于生存表或分析队列已经构建完成。

## 选择和追溯参考代码

读取 code-map 后按数据类型与候选来源选择主线，而不是只选相同癌种：

- bulk+先验集合的基础生存项目可从02接口开始。
- 单细胞marker+WGCNA+bulk整合可参考08；Scissor+hdWGCNA可参考16。
- 目标细胞虚拟敲除可参考19/23/24，按是否有网络整合、训练队列及验证设计选择。
- 需要多变量Cox对象预测或LASSO后再拟合，分别核对18或22的实际实现。

为每个将复用的阶段记录：原文件与版本、已检查的输入输出、目标脚本、保留的逻辑、修改及理由、已知待核实项。阶段来源可以不同，不必整套复制同一项目。

本技能包含提炼后的源码地图和明确列出的通用辅助脚本，原始项目R代码库没有随技能分发。能访问原文件时先读对应实现；无法访问时不得声称完成逐行移植。可以根据已核实的方法与数据契约重新实现，但明确标为“重新实现”并核查相关API；仅有摘要且方法细节不足的阶段标为草案或受阻，不生成貌似完成的算法实现。认证信息从当前会话运行时取得，不写入配置。

## 生成可审阅的项目

依用户目录约定和选定服务器参考组织文件，默认沿用根目录编号脚本、编号结果目录及`RData`的习惯；脚本与模块数量由实际路线决定。下面是新增项目的结构示意，阶段名和编号须按所选参考映射，不声称所有旧项目采用同一目录：

```text
project-XXXX/
  config.yaml
  r.00_rawdata.R            后续r.NN_<阶段>.R按参考项目及真实依赖安排
  00_rawdata/               原始数据、注释、临床及样本清单
  NN_<分析阶段>/           真实结果表、PNG和PDF，按阶段编号
  RData/                   单细胞对象、候选与模型/预处理工件
  project-XXXX方案_YYYYMMDD.docx / .pdf
  project-XXXX_report_YYYYMMDD.docx / .pdf
  workflow/                实际技术路线PNG及可编辑PPTX
  run.R                    按显式阶段依赖调度；不依赖交互全局工作区
  deliverables.tsv         本次逐文件计划、状态、参考和图号映射
  provenance.tsv           来源阶段、适配方式与修改记录
  RUN.md                   输入、运行、续跑、依赖和未解决项
  validation.md            实际做过的验证及其限制
```

已有项目不为统一结构迁移目录；可以保留现有`scripts/`接口，但须维护参考到新文件的明确映射。方法修正可增加最终多因素Cox、训练预处理和临床联合模型等必要对象，不因旧项目缺少这些工件而省略。图表与独立结果文件按模块产物目录准备，结果目录不能只有占位脚本。

具体要求：

1. **配置**：从示例配置填充癌种、终点、队列角色、数据路径及尺度、字段映射、候选路线、阶段和输出目录。新项目路径可创建；数据路径必须对应实际输入或明确标记为待提供，不能凭空假定文件存在。
2. **预检**：核对文件与字段、矩阵方向、ID唯一性与连接顺序、患者重复、基因覆盖、时间/事件定义及所选模块依赖；另核对GEO样本清单与作者原始材料、基因symbol注释来源、队列组织/人群、同源与重叠样本。输入含义尚未确认时在相应阶段给明确错误，不静默填补或用不合适的方法替代。
3. **分析脚本**：实现请求范围内的模块，完整新项目按默认路线组织；缺输入的阶段写明状态与依赖，不冒充已实现。患者划分、特征选择和预处理遵循主技能契约；把硬编码细胞、模块ID、基因数、路径和图标题改为明确参数或从结果取得。拟合与预测共享同一预处理和最终多因素Cox模型工件，列线图的联合模型另存。
4. **调度与续跑**：按阶段名或目标输出解析依赖，显式载入上游工件。未实现或受阻阶段不能被当成完成；不得简单以“某输出文件存在”判定它与当前配置和样本匹配。单阶段也可直接运行，无须为了形式新增复杂框架。
5. **运行说明**：列出输入格式、包与已确认版本、必填配置、按实际实现可用的命令、输出及续跑规则。远端资源和线程数依据任务确定，不沿用来源脚本的50/64核设定。没有取得环境版本时标明未核实，不编造锁文件。
6. **来源与变更**：区分源码适配、依据已读逻辑重新实现、仅据摘要草拟；列出修复的评分、事件字段、阈值、保存对象等变化，方便复核新旧结果为何不同。按标准核查表记录适用条款、实际值、工件、未达标项、偏离理由及已确认例外，不预填检查通过。

项目状态至少区分：信息待补、代码已生成、静态检查通过、合成用例通过、真实数据运行通过。最终报告当前达到哪一步，不把“生成成功”称为“分析完成”。

完整构建请求默认在结果生成后按 [report-writing.md](report-writing.md) 建立来源索引，并按 [document-format.md](document-format.md) 输出参考样式的Word/PDF报告。单独的代码任务只准备提纲与索引结构，不填入尚未运行的数值或结论。已有完整分析结果、仅要求写报告时，直接进入报告模式，不重跑整套分析。

## 有针对性的验证

对生成的R代码做静态解析，配置和脚本引用必须自洽。用小型合成数据检查实际改动影响的接口，例如样本/基因重排、训练参数复用、真实事件传递、缺候选或缺工件的诊断。若环境缺少分析包，可以完成静态与独立数据检查，但清楚标明尚未做该模块运行测试。

在有真实输入及相应执行授权时，先选择能检查数据契约的小规模阶段，再继续请求范围内的分析。模型性能数值、选出基因、显著性和生物学结论只来源于实际运行结果。真实数据未运行的项目仍可交付审阅，但不得承诺跨队列性能。
