# 与参考项目对应的文件和图表交付

用户于2026-10-28要求：使用本技能时，输出文件基本对应此前学习的服务器项目，可视化图片必须交付，方案和报告也沿用所学材料的格式。本规范适用于完整项目及其中被请求的阶段；不以旧项目的个别缺项、错误或未完成状态降低本次交付要求。

## 先选参考，再建立对应

从 [code-map.md](code-map.md)、[report-map.md](report-map.md) 和 [proposal-map.md](proposal-map.md) 选择路线相近的代码、方案、报告，三者可以来自不同项目，但要分别记录路径和版本。单细胞上游筛选、Scissor/hdWGCNA、虚拟敲除、bulk先建模后解释应分别匹配参考，不只按癌种选文件夹。

优先阅读技能中附带的 [五个项目参考脚本](project-code/INDEX.md)，核对选定脚本的实际写出调用、目录、图名和表头，再规划本次产物。旧的日期归档和根目录存在差异，记录采用版本。技能只附这五个项目的根目录脚本，不含完整服务器代码树、原始数据、附加资源和报告原件；其他项目若只能访问地图，将文件名标为“依据学习记录的对应”，不声称重新核验了原文件。

沿用适用的阶段编号、脚本命名、结果目录、图型、表头、TXT/CSV/XLSX和R对象习惯。无需迁移现有项目为新框架，也不要求所有项目有相同数量的脚本。新建完整项目默认保留根目录`r.NN_<阶段>.R`、编号结果目录、`00_rawdata/`、`RData/`和正式报告。若用户项目已经采用`scripts/`等结构，保留它并维护对应表。

对应是**文件用途、可读性、信息完整度和形式基本一致**，不是复制旧患者数据、固定结果数值或错误实现。方法修正后可新增必要产物；字段或格式有变化时写清旧接口、新接口、修改原因和受影响下游。

已读源码中的具体例子：project001项目的`05_DEG/01.DEGsList.txt`、`06_venn/01.hubgenes.txt`、`04_hdWGCNA/06.hub_module_gene_df.xlsx`，以及`RData/R.06_scRNA_done.Rds`、`RData/pbmc_all_with_subcelltype.Rds`，说明其阶段列表、表格和对象的交接习惯。project001的`04.risk_table.txt`应按对应训练/验证结果目录分别保存。它们是来源IO记录，不证明本轮重新检查了远端文件。`R.07_scRNA_Scissor.RData`虽叫RData却由saveRDS写出，新项目优先用正确的`.Rds`并记录兼容映射，不延续扩展名歧义。新的最终多因素Cox、训练预处理和临床联合模型也必须保存，不能因旧项目没有显式对象而省略。

## 按请求范围交付

| 本次任务 | 实际交付 |
|---|---|
| 完整构建预后项目 | 正式方案及流程图，R代码和配置，实际运行模块的完整结果表与独立图片，模型/预处理/中间工件，正式报告，运行与变更记录和逐文件清单 |
| 仅方案 | 参考样式DOCX和PDF，嵌入的技术路线及独立PNG/可编辑PPTX，数据角色和模块计划；将未来分析文件列为计划而非完成 |
| 仅代码 | 可运行的所选阶段实现、绘图及文件写出逻辑、配置和运行说明；未运行的结果图表与报告保持待生成，不用空文件代替 |
| 仅报告 | 复用现有真实结果，整理独立图片/表格和证据索引，生成嵌图的Word/PDF；缺图时先查既有输出和绘图代码，只在当前授权涵盖时重新绘制必要图，不重跑全套模型 |
| 续跑或修复 | 交付受影响模块及必要下游的结果，保留其他既有文件，并在清单中区分复用、新生成和未完成 |

未运行、缺输入或失败的模块记录具体原因及可继续步骤。它们不能写成完成，也不能为形式齐全填入示例图、旧结果或空对象。完整项目缺必需阶段时交付已有真实产物并清楚说明缺项；不会因为“文件清单有记录”就变成完整分析。

## 每个模块应产出什么

[module-output-catalog.tsv](../assets/module-output-catalog.tsv) 列出从已学流程提炼的模块级产物。根据本项目方案展开成具体文件，字段为推荐的语义产物，不宣称是所有旧项目相同的字面文件名。模块规则：

- 已选的单细胞质控、注释、关键细胞、候选整合、Cox/LASSO/多因素Cox、风险评价、外部验证和列线图均要有对应结果和图片。
- 完整设计的免疫、治疗相关、药敏、TMB以及关键细胞拟时序、通讯、代谢按输入和请求执行，已运行就导出其完整结果表及图，未运行则说明缺项。
- Scissor、hdWGCNA、PPI、虚拟敲除和其他扩展只在方案选择时要求；不为凑齐旧项目文件强加不适用算法。
- 候选、最终模型、临床联合模型、内部与外部评价的对象/结果分别命名。外部队列逐队列分目录，基因级及风险组分析分别标对象，不共用覆盖式`result.csv`。
- 表格保留全部有效检验和排名，图可以按预设规则展示部分。记录统计列、比较、单位、样本/患者、方法与校正；阴性结果不被删掉，零结果保留有表头的真实结果及原因。

## 图像交付和视觉对应

默认每张正式统计图交付独立**PNG与PDF**。PNG按最终尺寸导出，默认300 dpi，中文、坐标、点线和图例应清晰。PDF尽量保留文字和线条的矢量内容；热图或软件只提供栅格时如实保留栅格，不把PDF容器称为全矢量。用户指定其他格式或方法仅能输出固定格式时，记录实际格式与有依据的例外。

沿用选定参考的图型与信息组织，例如差异火山/热图、交集图、LASSO路径与交叉验证、Cox森林图、风险分布/生存状态/KM/时间依赖ROC/基因热图、列线图/校准、UMAP及marker气泡图。每幅图从本次结果绘制，重算图中基因、患者、细胞数和图例，不复制旧图中的标签与显著星号。颜色、分组顺序、基因名、时间单位和队列在整个项目一致，必要调整以清晰可读和方法有效为准。

不能用机器学习演示图或AI生成图代替统计结果；图表生成使用适用的R/Python绘图与分析工具。流程图和说明插图可单独制作，但标明设计或示意性质。技术路线按用户的可编辑要求交付**PPTX和PNG**，PPTX中的文字、框、箭头使用原生对象；不强制把全部统计图重画为PPT对象。

报告中必须实际嵌入相应图片，配图题和图注；独立图和嵌图须对应同一结果版本。仅给绘图脚本、图注、文件名列表、失效图片链接或Word中的空白位置，不算交付图片。主结果图在正文解释，补充图表归入对应补充结果并在正文定位。

## 正式方案、报告及归档

按 [document-format.md](document-format.md) 继承已学方案/报告的Word结构与版式。默认方案与报告均为DOCX及对应PDF，文件名沿用参考的项目编号、方案/report和日期模式；新编号、题名和日期由本项目填写，不复制旧项目身份信息。Markdown提纲、PPT总览或网页不是正式Word文档的替代。

完整交付除阶段结果外，保留配置、脚本版本/来源、运行日志、实际`sessionInfo()`、样本清单、模型与预处理工件、结果证据索引和模块状态。沿用用户或参考的代码/结果归档方式，归档与散文件版本一致；大体积原始数据和单细胞对象按项目存储条件留在可访问位置并给准确索引，不为“一个ZIP”复制无关患者数据或整个服务器目录。

## 文件清单和完成核查

从 [deliverables.template.tsv](../assets/deliverables.template.tsv) 填`deliverables.tsv`，每个具体输出一行，至少记录：

- `artifact_id`唯一ID，`scope`为`proposal/analysis/report/shared`，`module`对应实际模块，`kind`说明figure/table/model/object/code/document/workflow/log/index/data等类型。
- 同一统计图或流程图的多种格式使用同一`figure_id`、不同`artifact_id`；非图字段可空。
- `required`为`true/false`，根据已确定任务与适用模块填写。不是所有旧项目模块都必需；完整设计中缺输入的已选必需项仍保留`true`及受阻原因，不能仅为通过检查改成可选。
- `status`为`planned/completed/blocked/failed/not_applicable/not_requested`；未适用和未请求项须说明原因。必需项未完成时不称完整交付。
- `path`为相对本项目的实际目标文件，`reference_project/reference_path`记录参考对应，`source_result`定位底层结果文件，`report_anchor`定位报告章节/图号，`reason`说明缺项、偏离或复用情况。

`source_result`的多个路径用`|`分隔，可用`#`附表行/对象定位。已完成的统计图必须有实际可打开的底层结果文件；模型对象、表和单细胞对象均可作图来源，不能把图自身作为唯一源数据。

文件检查使用Python 3.10及以上版本和标准库，命令：

```bash
python3 <skill>/scripts/check_deliverables.py --root <project> --manifest <project>/deliverables.tsv --scope full
```

仅写方案用`--scope proposal`，仅代码或续跑按实际清单选择范围；若用户确实指定其他格式，设置`--figure-formats`、`--document-formats`或`--workflow-formats`并在清单及配置中记录依据。脚本检查必需项状态、实际文件、非空、常见文件结构、PNG/PDF配对、DOCX/PDF配对、流程图格式与图像来源文件。它不核验统计方法、数据真伪或排版，不替代R数据契约、图像目视和Word/PDF逐页检查。

最终按“参考文件对应 → 本次实际文件 → 报告图表 → 源结果/模型 → 核查状态”逐项复核。缺图、缺表、缺正式文档或版本不一致时继续完成受影响工作；确有输入/环境阻塞时交付可确认部分和具体缺项，不冒称已完成。
