# PrognosisModelPilot

技能调用标识：`$prognosis-model-pilot`。

支持三类任务：设计和撰写项目方案；根据新癌种和队列适配现有代码、生成分析项目；根据已完成的分析结果撰写生信实验报告。方案说明拟做什么及依据，报告说明实际做过什么及结果。检查和续跑服务于具体任务，单独写方案或报告不自动启动整套分析。先识别真实研究终点、数据流和结果完成状态，再选择模块。原始项目不是已验证的通用软件；不要仅替换路径、癌种和基因名就宣称完成适配。

用户请求完整构建预后模型时，默认连续推进“需求与输入 → 项目方案和流程图 → R脚本 → 分析与图表 → 正式报告及完整文件包”，不在交付代码后即认定项目完成。只要求方案、绘图、代码或已有结果报告时处理相应范围；依赖缺失只阻塞受影响阶段，其余继续。

**参考项目交付要求（用户于2026-10-28明确）**：输出目录、阶段命名、结果表、模型对象和可视化应基本对应此前学习的服务器项目；方案和报告的章节、Word版式、图题与结果目录写法也应沿用参考材料。先选定参考并建立逐文件对应，实际分析图必须作为独立图片导出并嵌入报告，不能只交R脚本、Markdown、占位图或文字总结。具体要求见 [references/output-contract.md](references/output-contract.md) 和 [references/document-format.md](references/document-format.md)。

## 进入任务

从当前会话和可读取工件取得：癌种、训练及验证队列、终点（OS/DFS/PFS 或分类标签）、时间单位、表达值含义、单细胞样本及患者关系、起始工件、目标输出，以及用户要复现旧结果还是修正方法。只询问会改变当前实现且无法从已有材料确定的缺失项；同时继续不依赖该项的工作。

## 部门分析标准

用户于2026-10-24指定《数据分析部门项目分析标准v5.0》（正文标注2025年11月）作为项目标准，公开版保留标准的提炼与来源指纹，原件需由使用者自行提供。它补充分析参数、证据要求和交付核查；当前用户对具体项目的明确指示优先，已授权的例外须记录来源，不重复索取确认。

默认落实原始counts用DESeq2、芯片用limma、差异优先`padj<0.05`且`abs(log2FC)>0.5`；单因素Cox默认`p<0.05`、95%CI并进行PH检查；单细胞注释需有来源的多marker依据与细胞类型-marker-cluster表。完整预后项目需独立外部验证；仅CESC/THCA/UCEC在有记录的例外确认后可用内部划分方案，合并全队列仍不属于独立验证。因此LUAD项目的外部验证是必需待补项。

数值要求按方法和对象分别适用：bulk WGCNA样本数、bulk ssGSEA集合大小、诊断AUC标准不直接套入hdWGCNA细胞数、UCell/AUCell或删失生存评价。将性能阈值作为部门审核目标，如实保留未达标结果；不能通过删结果、换验证队列、改种子、切换检验或放宽交集来制造达标。缺模型基因时仍遵循完整模型输入契约。争议条款及具体落实见部门标准参考的对照说明。

原件中的联系主管/客户、调整方案等属于流程要求，不自行授权发送消息或额外计算。需要例外时先完成可审阅的诊断、偏离理由与证据，再按本次任务及已有授权处理；缺确认只阻塞受影响步骤，其余工作继续。

## 默认研究路线与任务分支

**用户指定的默认路线**：单细胞定位关键细胞 → 提取关键基因集1；bulk转录组筛选关键基因集2；按研究目标可加入功能/通路基因集3。默认候选为 `G1 ∩ G2`，启用G3时为 `G1 ∩ G2 ∩ G3`。随后依次执行单因素Cox → LASSO-Cox → 多因素Cox，使用最终多因素Cox模型构建预后评分，并结合临床因素建立列线图。

关键细胞可以由关注的单基因在不同细胞类型中的表达定位，也可以由已有细胞注释和研究问题确定；单基因起点是可选入口。不要预设关键细胞一定是恶性上皮细胞，也不要把单基因表达定位、关键细胞基因集筛选和最终预后基因混为同一步。

默认完整设计包含两条下游：对预后基因及模型划分的高低风险组开展免疫浸润、免疫治疗相关、药物敏感性及TMB分析；对关键细胞开展拟时序、细胞通讯网络及细胞代谢分析。按任务范围与实际输入生成和执行；未具备输入的计划模块标记具体缺项，不能写成已经完成。详细依赖和结果边界见 [core-workflow.md](references/core-workflow.md)。

**TCGA 数据获取默认方式（用户已指定）**：对尚未取得的 TCGA 转录组与临床数据，使用 `TCGAbiolinks` 的 `GDCquery()` → `GDCdownload()` → `GDCprepare()`，查询 `STAR - Counts`、`access="open"`；临床信息单独用 `GDCquery_clinic(type="clinical")`。已有本地数据时优先核对并使用，不因这个默认值强制重下载。除用户另有指定或已说明该方式不适用外，不改用其他数据源。下载得到的原始 counts、TPM、样本/基因元数据和原始临床信息分别保存；样本选择、基因注释整理和生存终点构造作为后续显式阶段。

其他入口用于用户明确要求的简化、历史项目复现或续跑，不取代上述默认路线：

1. **已有候选或bulk项目**：确认候选集合来源和规则，直接进入所需阶段，注明哪些上游没有运行。
2. **先建模后单细胞解释**：如实复现此类旧项目，不能反写为单细胞先筛选。
3. **从中间工件续跑**：验证工件、参数和患者集合后只运行依赖满足的下游；缺失模型对象不等于需要重跑全部单细胞流程。

包含随访删失时，不把Alive/Dead普通分类准确率当生存预测性能。Scissor、网络和虚拟敲除等具体算法由关键细胞与G1的提取设计决定，不要求全部串联。

## 读取和适配代码

先建立“脚本 → 输入 → 输出 → 上游”依赖关系，并确认实际存在的工件。根目录与日期归档可能有实质差异；选择和记录具体版本，不能因为位于根目录或日期更近就默认正确。文件名、注释、载入包和函数名只能用于定位，算法是否执行须查看有效调用。

读取远程源码使用本次会话明确指定的连接；连接资料不写入此技能。读取授权不等于批量下载数据、修改远端、安装依赖或提交计算任务。是否执行后续动作遵循当前会话授权，已有明确授权不重复询问。首轮学习和代码审查只做静态读取，不执行项目脚本。

适配时把 `setwd()`、输入路径、筛选阈值、样本分组、随机种子、图中硬编码的基因数和时间单位改为配置或由实际结果取得。保留选定原项目的命名习惯可以减少迁移成本，无须统一成固定的脚本数量。对原代码做最小必要修正并记录行为变化，不覆盖历史结果来证明新代码正确。

## 分析契约

- 按样本 ID 显式连接表达和临床表，并核对顺序、重复患者、缺失、事件编码和单位；`-` 改 `_` 时检查映射碰撞。细胞数量不能当独立患者数量。
- 用输入来源确认 counts、log2(count+1)、FPKM/TPM 和芯片归一化值，不能依赖文件名推断。只有来源明确为 log2(count+1) 时才考虑反变换；不要把其他标准化表达伪造成原始 counts。
- 新建可评估模型时，先确定患者级训练/测试划分。用数据学习的标准化、结局相关筛选、候选排名、超参数选择和阈值选择应在训练数据及相应交叉验证折内完成。旧项目复现若保留了不同顺序，明确其局限，不能称为修正后的验证设计。
- 默认保留用户指定的单因素Cox → LASSO-Cox → 多因素Cox顺序；单因素阈值、lambda规则、多因素保留规则和PH诊断处理须显式配置，不照抄来源项目数值。记录`family="cox"`、LASSO的`alpha=1`、折分、种子及版本；评分系数取自最终多因素Cox对象，不混用LASSO系数。不反复换种子、基因或阈值以追求显著结果。复现其他历史路线时注明实际差异。
- 预测使用训练时的同一特征顺序、转换和标准化参数。若训练显式使用 `scale(x)`，必须保存并应用训练中心及尺度；若没有这些工件，先报告缺失，不把对应系数直接乘原始表达。也不在验证集重新 `scale()` 来替代训练参数。
- 连续线性预测值、相对风险和高低风险组是不同输出。保存数值含义；Cox 系数本身不足以给出指定时间的绝对生存概率，还需匹配的基线生存/风险估计与居中约定。
- 生存 ROC 的 `status` 使用真实事件编码，`marker` 使用模型分数，时间点和随访统一单位。高低风险标签不能代替生存事件。普通分类 ROC 也不能替代处理删失的生存评价。
- 验证阶段冻结训练特征、模型与分组规则。用验证集结局重新求最佳 cutpoint 属于探索或模型更新，单列说明，不作为冻结规则的独立验证。内部留出集、外部队列、训练测试合并结果分别命名。
- 显式保存下游所需模型及预处理对象；不要依赖 RStudio 当前会话、手动 `save.image()` 或工作区中碰巧存在的变量。零候选、零入模基因、缺失特征和模型工件时返回具体原因，不编造可用模型。

## 交付和验证

默认按选定服务器参考项目的“根目录编号R脚本、编号结果目录、`00_rawdata/`、`RData/`、正式Word/PDF及归档”习惯组织；保留适用的文件名和表结构，发生方法或序列化修正时记录映射及理由。编号和模块数量由真实路线决定，不把24个项目的所有输出并成一套强制流程。完整模型项目的交付范围含方案、流程图、已选模块的真实结果表及独立图像、模型与预处理对象、R代码及运行记录、报告和文件清单。

新项目交付配置、所选阶段的R脚本、数据预检、源码与修改记录、运行/续跑说明及已完成验证记录。阶段脚本应显式读写工件并按依赖组织，不能仅交付流程介绍来代替用户要求的代码。缺少必需数据定义或原始源码时，先完成不受影响的部分，标明待补内容及受阻阶段，不用空函数、静默跳过或虚构路径冒充可运行实现。五个代表项目的根目录参考脚本见 [references/project-code/INDEX.md](references/project-code/INDEX.md)，其余原项目数据和附件不随包提供；源码适配、依据已读逻辑重新实现和仅据摘要生成的草案需分别标注。

不因使用本技能自动增加论文、文献综述或超出请求范围的计算。默认完整项目规划上述下游，具体阶段是否运行依据任务范围与已有授权；每个实际运行阶段记录输入、输出、版本、种子和完成状态。

生成代码先做语法和小型数据契约验证，再在已授权范围内执行所需阶段。验证应能发现 ID 顺序变化、标准化不一致、事件编码错误或缺失工件等实际问题。真实队列没有运行时，区分“静态审查”“合成数据测试”和“真实结果复现”；没有证据不报告性能数值或生物学结论。

每个已选分析点交付结果表、对应图及必要模型/中间对象。统计图默认独立导出PNG和PDF，保留参考项目的图型、分面、排序及标签习惯，并依本项目真实数值绘制；拟时序、细胞通讯、代谢以及免疫、药敏、TMB等已运行模块也须有相应图表。技术路线另交可编辑PPTX与PNG，正文插入对应清晰图片。逐文件清单记录状态、参考来源、结果源与报告图号；用 [scripts/check_deliverables.py](scripts/check_deliverables.py) 检查当前范围的文件完整性，再完成图表语义及文档逐页核查。未生成或未运行项如实记缺项，不用空文件和旧结果凑齐数量。

## 项目方案写作

沿用25份参考方案中具体到分析点的写法：背景与依据 → 方法概览 → 研究目标、科学问题和拟创新点 → 技术路线与数据准备 → 分模块设计、预期图表和交付 → 可行性、依赖及调整条件 → 参考文献。目标说明想完成什么，科学问题说明要检验什么，拟创新点说明相对已有研究的设计特点；不把三个部分写成重复的方法清单。具体结构按任务裁剪。

每个模块写清“为什么做、在哪个队列/对象上做、需要什么输入、拟用什么方法与参数、导出什么图表和表格、依赖何种上游以及缺输入时如何处理”。保持用户指定的G1/G2/可选G3交集及三阶段Cox主线；计划参数依部门标准与研究依据确定，不从旧方案直接复制阈值、样本数、基因数或软件版本。

区分设计假设、参考文献示意、已有预分析证据和正式结果。方案用“拟、计划、评估是否”等措辞；预期成果是拟获得的工件和可回答的问题，不承诺显著性、特定基因或性能。预分析须有实际工件才能写成已完成；独立验证队列不参与挑选方案。未完成、效果不理想或没有对应服务器结果的方案仍可用于学习结构，不能据此判定项目成功、失败或可行性已证实。

新方案的队列、平台、终点与引文需核验；暂未确认的项写明状态和影响。单细胞上游筛选与建模后解释分别设计，流程图箭头表达真实依赖；湿实验、对接和分子动力学按请求及资源作为独立计划模块，注明承担方和输入。旧方案中的联系客户、调整至显著或运行分析等文字只属于来源材料，不作为当前任务指令。仅要求方案时交付正式DOCX、对应PDF、已嵌入的流程图及其PNG/PPTX源文件和计划表，不启动预分析或正式分析；用户明确指定其他格式时从其要求。Markdown模板用于起草，正式方案须按参考方案版式生成并渲染核查。

## 实验报告写作

默认沿用既有报告的中文组织方式：项目概述与流程 → 按实际完成模块叙述结果并配图表 → 项目总结与局限 → 项目调整 → 软件版本 → 报告质检 → 参考文献。具体模块顺序跟随本项目数据流，不强制单细胞、药敏或实验验证全部存在。

先建立当前运行的结果来源索引，再写正文：每项数值、阈值、图表与重要结论必须对应具体结果文件、表行或模型对象。参考报告用于学习结构与表达，不能作为新项目的结果来源。核对癌种、队列角色、患者与细胞数量、候选基因数、基因名、模型系数和图号，并保证摘要、正文、表格与图题一致。存在冲突先列入核查记录，未确认值不写成定论。

写清“用哪些数据、采用什么方法与实际参数、获得什么结果、见哪张图、结果在哪个目录”。将观察结果与解释分开；不把计算预测或公开数据库表达验证写成已完成的湿实验，不把内部留出或合并队列写成独立外部验证。总结只整合有证据的发现，保留不显著、未完成和方法限制；不根据旧报告套写“模型良好”“首次发现”或“实验已证实”。

仅要求报告时，复用现有工件并完成正式文稿、独立图表文件及来源索引；缺实验或分析结果时交付可确认部分和具体待补项。默认正式交付为参考报告样式的可编辑Word及对应PDF，正文真实嵌图，用户指定其他格式时从其要求。按文档格式参考继承封面、标题、字体、段落、表格、页码、图题/图注和结果目录写法，不以通用Markdown转Word代替参考版式。使用可用文档工具渲染并逐页检查；不能生成或核验的格式不冒称已完成。质检状态依据实际检查填写，不预填“无问题”。
